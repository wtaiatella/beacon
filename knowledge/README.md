# Knowledge Base

This directory holds **local** structured project context, generated by **`/kb`** — optional, complementing the per-ticket pre-plan domain specialists that already ground every ticket in the current code.

Each project gets its own folder with focused section files:

```
knowledge/
├── myapp/
│   ├── _index.md          # overview, stack, structure (always loaded)
│   ├── architecture.md    # components, patterns, flows
│   ├── api.md             # endpoints, auth, contracts
│   ├── data-models.md     # schemas, entities, migrations
│   ├── dependencies.md    # deps, integrations, external services
│   ├── infrastructure.md  # CI/CD, containers, deployment model
│   └── conventions.md     # naming, error handling, config
```

**Agents load selectively** — `/plan` reads the index + sections relevant to the feature. `/dev` reads index + conventions + api. This keeps context costs low even for large codebases.

## Usage

```
/kb myapp/              # full build (expensive, run on first onboarding)
/kb myapp/ deploy/      # multiple projects
```

**Day-to-day maintenance:** **`/summary`** automatic KB patching is **not** the default; optional legacy local patches only when your team explicitly keeps a local KB — see **`.cursor/agents/summary.md`**.

## These files are tracked in git

The knowledge base is committed to the workspace repo and shared across the team. Everyone benefits from the same project context.
